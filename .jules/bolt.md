## 2024-05-10 - Avoid Expensive Date Instantiation in Sort Comparators
**Learning:** During array sorting of objects containing ISO 8601 date strings, using `new Date(a.date) - new Date(b.date)` inside the sort comparator leads to O(N log N) `Date` object instantiations on every re-render. This is a massive hidden bottleneck, especially when filtering/sorting derived state in React without memoization. Furthermore, JS sort engines require strict weak ordering, so comparators *must* return `0` for equality when switching to direct string comparison.
**Action:** When sorting by ISO 8601 date strings, use direct string comparison (e.g., `a.date < b.date ? 1 : a.date > b.date ? -1 : 0`) and always wrap such derived state calculations in `useMemo` to prevent redundant computations across renders.
