## 2024-04-18 - Replacing `useEffect` with `useMemo` for derived state
**Learning:** Using `useState` updated via `useEffect` for client-side filtering/sorting derived state (e.g., `Marketplace.jsx`) creates an unnecessary double-render cycle. The first render reflects the changed dependency (like search term or category change), and the second render is triggered by setting the derived state inside the `useEffect`. Filtering ~10,000 items takes around 90ms. This cost incurred twice when state settles provides a noticeable lag on low-end devices.
**Action:** Use `useMemo` directly during the render cycle to compute derived state instead of syncing state variables via `useEffect`. This eliminates the redundant re-render and ensures state stays perfectly in sync without layout thrashing.
