## 2024-05-17 - [Supabase Global Subscription Anti-Pattern]
**Learning:** [When subscribing to real-time changes in Supabase (`postgres_changes`), failing to provide a `filter` parameter causes the client to receive updates for *every* row change in the table globally. In components like `SellerQueries`, this triggers a refetch of the user's queries for every single change across the entire application, creating a severe N+1 refetch bottleneck that scales linearly with the application's overall usage, not the user's specific activity.]
**Action:** [Always apply a database-level filter (e.g., `filter: farmer_uid=eq.${user.id}`) to `postgres_changes` subscriptions when the component only cares about a subset of data (which is almost always). Ensure the filter dynamically updates based on the current context (e.g., active tab) if necessary.]
